Bug found and fixed:

Game 2 crashed with AttributeError: 'str' object has no attribute 'get'. Root cause: extract_json() in llm.py only checked that json.loads() did not raise an exception, it never checked that the parsed result was actually a JSON object (dict). Somewhere in a long, heavily-reasoned Sonnet 5 turn, the model returned a bare JSON string (for example "P07") instead of the required object with reasoning, action, and target fields. That string is valid JSON, so it parsed without error and was passed to downstream code that assumed a dict, which crashed on .get().

This contradicts the harness's own documented design: malformed model output is supposed to be logged as MALFORMED_OUTPUT and retried, never crash the game.

Fix applied: extract_json() now checks isinstance(data, dict) after parsing, both on the direct parse and on the fallback regex-extracted parse. A non-dict result returns None, which triggers the existing retry-then-coerce path (re-prompt once, then fall back to referee coercion defaults) instead of crashing.

Verified with three probe cases before committing: a bare JSON string returns None, a bare JSON list returns None, a normal JSON object with or without markdown code fences still parses through correctly.

This defect was not observed in the earlier Haiku run (5 games, 3 completed before a sandbox restart interrupted it). It surfaced specifically under Sonnet 5 at effort=high, where responses are longer and more elaborate, which is exactly the kind of harness defect the project is built to find by using a stronger model.
